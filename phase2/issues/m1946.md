Follow-up from a longer test run on **26.10.1 / MariaDB 12.3.3** (3-node Galera, ~9 GB data, 50 tps load): we ran the full-cluster crash (`kill -9` all mariadbd) **three times**. The nil `wsrep_cluster_state_uuid` appeared after **2 of 3** runs (once on 2 members, once on all 3). In the following node power-off tests the rebooted member never rejoined (900 s timeout, twice). The second run ended in a total outage with the operator looping on `error recovering cluster: error getting bootstrap source: bootstrap source not found` (all recovered UUIDs nil). `forceClusterBootstrapInPod` recovered it in 353 s without loss of acknowledged writes. So this reproduces reliably for us. It is not a one-off.

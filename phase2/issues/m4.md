**mariadb-operator 26.10.1.** Smaller usability issues found in testing:

1. **PITR archive interval is fixed at 10 minutes** (`pkg/binlog/archiver.go`: `archiveInterval = 10 * time.Minute`), so recovery-point exposure is up to ~10 min. In our test `LAST RECOVERABLE TIME` stayed empty for 10 min after the base backup. Please make it configurable (e.g. `PointInTimeRecovery.spec.archiveInterval`).
2. **PITR bootstrap into a non-replication MariaDB** (`replicas: 1`, no `replication`) fails with `Error reconciling PITR: error getting start GTID: error getting agent client: error getting agent base URL: error getting agent: high availability must be enabled`. Either support it, or validate it in the webhook with a clear message and document it in pitr.md.
3. **User CR default `maxUserConnections: 10`** is too low behind MaxScale readwritesplit: each client session holds one backend connection per server. 16 client sessions gave `ERROR 1226 ... exceeded the 'max_user_connections' resource (current value: 10)` on every backend, and MaxScale closed the sessions (`Lost connection` in clients). Consider a higher default or a warning in sql_resources.md (related: #922).
4. **Password rotation needs the `k8s.mariadb.com/watch` label** on the Secret. Without it, changing the password in the Secret is silently ignored (old password still worked after 10 min); with it, applied in 7 s. sql_resources.md doesn't mention this, and its examples create unlabeled Secrets (related: #362).
5. **Operator upgrade keeps the old MaxScale image.** After `helm upgrade` 26.6.0 -> 26.10.1, an existing MaxScale CR without `spec.image` stays on `mariadb/maxscale:23.08.5` (the previous default). The new default 23.08.13-2 only applies to new CRs. Release notes should say so, especially since 23.08.5 is still BSL-licensed until 2028 while 23.08.13 is GPLv2 since 2026-09-21.
